# 三方向：三种好设计，不是三种皮

任何新视觉设计，先出三个方向的真实初稿给用户选。这道门本身不变：100% 触发、指定风格或品牌也不豁免、摆出来就停、选择落档 `direction-approved.md`（豁免条件见 SKILL.md「窄桥」）。

这份文件讲**三个方向怎么生成**。

## 为什么这样做（两轮实测的结论）

**第一轮问题：三版只换了皮。** 旧做法让三个 subagent 吃同一份 spec，分别跑「最佳设计师 / 现实参照 / 秒数轮盘」。真实产出里，三版常常是同一个骨架换颜色和字重，而且一起滑向暖奶油底、衬线大标题、陶土色点缀、全大写小标签——这是模型自己的默认审美（Claude 的交互配色），Anthropic 官方 frontend-design skill（2026）把它列为 AI 生成页面聚类的第一类。

**第二轮问题：矫枉过正。** v3 曾强制每个方向先定一个「大想法隐喻」、信息组织方式三选三不同。三方向确实拉开了，但用户盲选时 4 题里 3 题选了旧做法，理由是「隐喻用力过猛」「新版自己也开始雷同」：页面被整个做成档案柜、借书卡、地铁线路图，同一个地铁图在两个不相干的题目里各出现一次。用户点名肯定的，是借一种结构语言、克制用色的那一版。

所以现在的做法是：**三套逻辑照旧（它们出的东西更好看），加三道护栏**——不落进模型的默认家族、不和最近的项目撞、不用力过头——再让脚本查三版有没有撞。

## 流程

### Phase 1 · 澄清需求＋主动索要参考

这是整个项目唯一的一轮提问（选定方向后不再重问，`references/workflow.md` 的题库从这里挑），一次最多 3 个问题：受众 / 核心信息 / 情感基调 / 输出格式。同时一次问全参考材料：项目叫什么、有没有 logo / 品牌色 / VI / 字体规范、有没有「就要那种感觉」的网站或截图；都没有就说一句「你看着办」。

用户不回应就不枯等：按最佳判断补齐假设（标 assumption），直接往下做，用「看得见的东西」代替继续追问。

给了具体品牌或产品名（能去官网找到 logo 的那种）→ 加走品牌资产协议（`references/brand-asset-protocol.md`），三个方向全部基于同一套真实资产，差异在诠释。普通主题名（咖啡、历史、健身）不是品牌，别去找「咖啡的 logo」。

### Phase 2 · 顾问式重述

用自己的话重述本质需求、受众、场景、情感基调、用户没说出口的期待。以「我直接做 3 个不同方向的真实版本给你看」结尾，不要以「你想选哪个方向」结尾——没看到视觉之前的选择是无效的。

### Phase 3 · 固化 spec

写一份详尽的设计 spec，它是三个方向的共同输入：项目是什么、受众与场景、核心信息分点、情感基调、**输出格式与尺寸（必填，三版必须统一，否则没法横比）**、已知约束、图片需求。spec 只写「要说什么」，不写「长什么样」——长什么样是方向卡的事。

### Phase 3.5 · 素材前置

按 `references/materials.md` 先判档位、取齐内容必需的真图和具名产品的 logo，三个方向共用。

### Phase 4 · 先写三张方向卡（主 agent 写，写完再开工）

开写之前先看两样东西：

```bash
# $HD = 本 skill 的根目录（SKILL.md 所在目录），不是用户的项目目录
python3 "$HD/scripts/learn.py" direction color <题材关键词>   # 这个用户的偏好＋过去的教训
python3 "$HD/scripts/design_lint.py" ledger                     # 最近交付过的样子和用过的参照：这次主动避开
```

**三套逻辑，各出一个方向：**

- **方向 A · 最佳设计师**：深呼吸，认真想——假如预算没有上限，世界上最适合为「这个用户、这个题材」做设计的工作室或设计师是谁？（Pentagram、Collins、原研哉、Massimo Vignelli、吕敬人……按题材选，别总是同几个名字）启用他的设计思维从头做，而不是模仿他某件作品的外观。
- **方向 B · 现实参照**：选一个和需求最相关、你确定设计极出色的真实作品（获奖网站、出版物、App、展览导视、唱片封套、科学插图都行），用 WebSearch 核实它存在，拆出它的**设计语言**——网格、字体关系、色彩比例、图文关系、留白节奏——迁移到用户的内容上。**迁移的是语言，不是把页面做成那个东西**：借杂志的排版规则，而不是把网页做成一本杂志的道具。
- **方向 C · 秒数轮盘**：取当前秒数（`date +%S`；Windows PowerShell 用 `(Get-Date).Second`），`秒数 % 20 + 1` 从 `references/design-styles.md` 对应分区抽一号（网页 / PPT / 信息图按产出形态选）。作用是打破模型偷选安全极简的惯性。抽到的风格**按七成力度用**：取它的结构和气质，不把饱和度、字号、装饰全部拉满。抽到和外观账本最近 3 个交付同类、或落在「暖奶油＋衬线＋陶土色」家族（除非品牌本身如此）的，顺延下一号；还原度 <70% 的标注哪部分降级。

**用户指定了风格或品牌时**：三套逻辑都在那个语境里各出一种诠释，颜色可以都受品牌约束（compare 加 `--brand`，只比骨架）；轮盘只在和语境兼容的风格里抽。「Apple 风格」是一个语境不是一个设计。

**方向卡**写进项目目录的 `directions.md`，每张一段：

| 栏 | 写什么 |
|---|---|
| 逻辑与来源 | A 哪位设计师 / B 哪个作品（附出处）/ C 抽到几号哪个风格 |
| 借的是什么 | 从来源里拆出来、要用到这次设计上的具体规则：网格、字体关系、色彩比例、图文关系 |
| 主角素材 | 画面主角是什么：真图、生成图、程序化材质、数据图像、巨字……（档位见 `references/materials.md`） |
| 骨架 | 版式结构一句话（三版骨架要互不相同） |
| 胆量花在哪 | 唯一一处最大胆的地方，其余服务内容 |
| form 来自内容的哪里 | 一句话：这个设计里哪个东西是这个题材才有的 |

**三道护栏，写完卡对一遍，过了才开工：**

1. **不落进默认家族**：三版里最多一版是「浅暖底＋衬线标题」；不用暖奶油＋陶土色，除非品牌本身如此。
2. **不和最近的项目撞**：外观账本里反复出现的样子和用过的参照，这次不再用；至少一版彻底离开。
3. **不用力过头**——三版里最多一版做以下任何一件事，而且只在内容真的需要时：
   - 把整页做成一个道具或实物仿制（借书卡、档案柜、票据、处方笺、说明书）
   - 套一个万能隐喻：地铁线路图、终端命令行、报纸头版、仪表盘——它们在任何题材上都套得上，正是新的默认外观
   - 把饱和度、对比、字号拉满（满版撞色块、巨字海报硬塞进 App 界面）

   判断方法：**把这个手法去掉，信息是更清楚还是更糊？** 去掉反而更清楚，它就是过头。隐喻和风格是调味，不是容器。

一个例子（题材：一家做了三代的手工酱油厂官网）：

- A · 最佳设计师｜原研哉｜借的：大量留白、素材本身做主角、极少的字｜主角：陶缸与晒场的真实照片｜骨架：一屏一张图一句话，纵向慢节奏｜胆量：首屏一整张盐霜特写｜form：酱油要晒 180 天，节奏就放慢
- B · 现实参照｜昭和时期日本药品包装（附出处）｜借的：两色套印的配色比例、竖排标题与横排说明的关系、细框分区｜主角：产品瓶身实拍＋两色套印的标签式标题｜骨架：左竖排标题、右三栏内容｜胆量：只用两种油墨色｜form：老字号的「方子」气质（借的是版式，不把页面做成一张处方笺）
- C · 秒数轮盘｜抽到「媒体级粗野主义」，按七成力度｜借的：大字号反差和模块网格，不用满版纯黑｜主角：超大汉字「酱」切进首屏｜骨架：模块网格，图文交错｜胆量：首屏字号反差｜form：一个字讲完一家酱园

### Phase 5 · 并行构建，每版自检

每个 subagent 只拿 spec ＋ 自己那一张方向卡 ＋ 共用素材，独立 context、互不参考。不支持 subagent 的 runtime 串行做，每版开工前只读 spec 和自己的卡，不参考已做的版本。

构建规则（三版共用）：

- 用户真实内容，不用 Lorem；三版同内容只换设计
- 可读性硬底线：网页正文 ≥14px、标签 ≥12px；deck 正文 ≥24px、标签 ≥16px；手机看的 1080 宽长图正文 ≥36px、标签 ≥28px；正文对比度 ≥4.5:1；留白要是构图，不是内容缺席
- 单文件 HTML；单文件交付时图片和 logo base64 内嵌
- deck 用 deck 外壳，每方向出 2 页代表页（`references/modules/deck.md`）
- 存项目目录 `design-demos/[方向名].html`，截图 `npx playwright screenshot file:///… out.png --viewport-size=1440,900`（deck 用 1920,1080）

三版都做完后跑：

```bash
python3 "$HD/scripts/design_lint.py" check design-demos/*.html           # 红灯必修；黄灯要么改、要么在交付说明里写为什么是选择
python3 "$HD/scripts/design_lint.py" compare design-demos/*.html         # 两版撞了 → 撞的那版回到方向卡，换骨架或换来源，不是换颜色
#   品牌约束了颜色字体加 --brand；App 原型多台手机并排加 --ignore-layout；deck 加 --viewport 1920x1080 --min-body 24 --min-label 16
python3 "$HD/scripts/design_lint.py" ledger check design-demos/*.html    # 全部都和最近项目撞了 → 至少一版要彻底离开
```

确认 `design-demos/` 下真有 3 个 html 再往下。黄灯的意思是「改掉那个结构，或写清为什么是选择」——换个符号、换个写法躲过检测不算改。没装 Python 版 playwright 时脚本会跳过并提示安装，这时用截图肉眼对照三版，并把这件事写进交付说明。

### Phase 6 · 展示，然后停

一起摆出三张截图，每版附它的方向卡摘要（逻辑与来源、借的是什么、主角素材）和一句「form 来自内容的哪里」。摆出来就结束这一回合等用户选，包括无人值守会话。

### Phase 7 · 用户选了之后

- 把「展示了哪几版、截图路径、用户的原话」写进 `direction-approved.md`
- 用户的话里有对品味的明确表态（「这个完全不 AI 感」「太素了」「要更像杂志」），用 `learn.py add --kind preference` 逐字记下，并写明适用范围
- 混合选择（「A 的布局＋C 的颜色」）照做，记下他混的是哪两栏——这比记住他选了哪个颜色有用；他说某版「过头」「太素」也逐字记下
- 进入执行；交付后 `design_lint.py ledger add <最终文件> --project <名字> --note "<来源：设计师/作品/风格>"` 记一笔外观账，下次连参照一起避开
